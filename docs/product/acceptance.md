# Acceptance criteria

Purpose: define observable results for the first validated StockMesh capability. These criteria are provisional until the user selects a concrete pilot workflow.

| ID | Observable criterion | Failure condition |
| --- | --- | --- |
| AC-01 | A synthetic or explicitly authorized corpus can be ingested with stable source identity, timestamps, and provenance retained. | A canonical or derived record cannot be traced to its source. |
| AC-02 | The organizational profile can represent people, units, Events, statements, Stances, Relations/Flows, and State without forcing every Claim into a binary fact. | Observations, reports, inferences, and judgments collapse into one status or company fields leak into the universal core. |
| AC-03 | Adding one new evidence item returns a bounded set of relevant historical and network context. | Results are context-free or cannot identify the evidence used. |
| AC-04 | A user can inspect a local network and evidence-backed timeline for a selected entity or event. | The view hides time, relation meaning, or provenance. |
| AC-05 | Stance analysis distinguishes direct statements from model interpretation and shows uncertainty or contradiction. | Inferred Stance is presented as a direct quote or established fact, or Stance is confused with a Position projection. |
| AC-06 | Identity resolution and interpretations can be corrected without modifying raw evidence; derived views can be rebuilt. | Correction destroys source history or requires manual mutation of raw data. |
| AC-07 | Unauthorized, provenance-free, or materially ambiguous input is quarantined or rejected with a reason. | It is silently promoted into canonical analysis. |
| AC-08 | A human reviewer can reproduce one analysis path from output to sources and processing identity. | The path depends on hidden state or unrecorded prompts. |
| AC-09 | Public-repository outputs contain no private conversation locator or linkable case detail; reusable examples are synthetic unless a de-identified template was explicitly authorized. | A case, locator, or identifying combination is committed by default. |
| AC-10 | The same authorized event set and projection identity reproduce the same as-of Position, while later corrections create a traceable new projection. | A Position depends on hidden mutable state or overwrites history. |
| AC-11 | Position evaluation declares perspective, objective, horizon, risk policy, evidence cutoff, vector dimensions, weights, and uncertainty. | A universal opaque “person” or “situation” score is presented. |
| AC-12 | Where the profile supports strategy, the LLM analysis boundary can generate a context-dependent branch set under declared search budgets; every materialized Position has a traceable multi-party Evaluation, and retained alternatives show assumptions, modeled response/cause, resulting Position, uncertainty, and replan trigger. | Candidate count/depth is hard-coded as a product limit, an expanded Position lacks Evaluation, or the system emits one confident future without alternatives or assumptions. |
| AC-13 | A user can select any historical or hypothetical Position, reconstruct its exact evidence/context cutoff, fork a new analysis, and label any hindsight view separately. | Later knowledge or a sibling branch silently leaks into the reconstructed decision. |
| AC-14 | The Web workbench supports the full pilot loop: stage evidence, inspect Timeline/Position/Node, ask for analysis, compare Trajectories, and correct a Claim. | The user must edit internal graph or database records to complete the loop. |
| AC-15 | The Web workbench can call branch-specific context, LLM analysis, Method, search, selection, and replay operations; an Agent Skill or CLI client can call the same capabilities without direct canonical writes. | A client must access private storage, loses branch context, bypasses validation/review, or receives materially different analysis semantics solely because of its transport. |
| AC-16 | The same universal core can represent at least three materially different synthetic domains—organizational interaction, resource/energy flow, and collective or machine coordination—through profiles without adding company-only fields to the core. | A new domain requires pretending every node is a person, every edge is a social relationship, or every event is communication. |
| AC-17 | When the optional episode/game-record view is enabled, an unfinished record preserves confirmed history, alternatives, and a resumable frontier; a later actual step appends independently and may link to old forecasts through Forecast Assessments. | Optional view semantics leak into every domain, advice is silently recorded as fact, or later reality rewrites the old prediction. |
| AC-18 | In the synthetic organizational dialogue, one reviewed Utterance can be traced through before-Position, evidence/Claim, communication Event and optional Action, Transition, after-Position, mode, and branch membership. | A sentence is stored without its contextual Position change, or its inferred strategy/outcome is treated as observed fact. |
| AC-19 | An analysis identifies every contributing Method/version, its macro or micro scale, required inputs, assumptions, limitations, uncertainty, and distinct outputs; the underlying evidence remains unchanged. | A named school, heuristic, historical analogy, or model silently becomes fact, or a hybrid answer hides which method produced which claim. |
| AC-20 | Main Line history and Variations render as one navigable branch graph; a user can pin several desired forecasts and resume an unchanged branch from cache while its hypothetical mode remains visible. | Pinning a branch promotes it to history, cache reuse cannot identify its context/configuration, or returning to an earlier Position destroys later branches. |
| AC-21 | The initial organizational profile can run the selected transparent SNA Method pack and show each algorithm's typed/time-bounded input, raw metric output, caveat, and LLM interpretation separately. | A centrality, community, or diffusion result is presented as a social fact or silently merged into the LLM analysis. |
| AC-22 | Every Variation declares `forecast`, `counterfactual`, or `exploratory` purpose independently from realization status. A later actual Event can link to one or more forecasts as matched/partial/diverged, or remain an unmatched surprise, without changing either record's original mode. | Prediction and fact are modeled as mutually exclusive states, a realized match rewrites the old forecast, or an imaginative branch is counted as a failed prediction. |
| AC-23 | A reviewed real reaction can produce evidence-linked, time-bounded candidate revisions to Pawn/Node profile Claims; accepted revisions append a new version while preserving alternatives and the old profile snapshot. | One action silently rewrites personality/ability/style, prediction text becomes profile evidence, or an old Position changes after later learning. |
| AC-24 | An `expired-unobserved` forecast assessment identifies the elapsed horizon and adequate observation coverage; otherwise the result remains pending or unknown. | Missing input is treated as proof that an Event did not happen. |
| AC-25 | Forecast replay uses the exact branch-root profile and treats attributes as stable unless an explicit hypothetical profile Transition was part of the branch; a separately labeled hindsight view may use later revisions. | Later profile learning leaks into the original forecast or simulated attribute changes occur without traceable assumptions. |
| AC-26 | Forecast residuals can update a separately attributed calibration record for the responsible provider/model, Method, and Search Policy while subject/profile Claim learning remains independently reviewable. | A model miss automatically changes the Pawn profile, or model calibration cannot identify the original run and assessment evidence. |

Engineering scaffold, schemas, file counts, or fixture-only tests do not prove these criteria. User acceptance remains a separate human decision.
